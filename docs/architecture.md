# Architecture and Trust Boundaries

On Windows, `internal/inventory` also performs read-only discovery of PHP FastCGI application registrations and handler mappings in the standard global IIS `applicationHost.config`. XML input is bounded to 8 MiB. Configured CGI executable paths are recorded without executing them, and secret-bearing arguments and environment settings are excluded from reports. Actual active worker processes, site-specific effective configuration and binary provenance remain outside this discovery contract.

The executable is built from the Go standard library. `internal/inventory` discovers candidate PHP CLIs and inspects each with a bounded, argument-separated subprocess. `internal/assessment` evaluates release floors from the PHP project's October 2026 advisories and explicitly declines to infer vendor backports. `internal/remediation` provides a read-only Debian/Ubuntu APT update planner with strict executable/package ownership binding, fixed-floor comparisons, candidate-origin checks and simulation constraints. `internal/mitigation` handles only an explicitly selected `php.ini`, using an integrity-checked private backup, exclusive transaction lock, atomic replacement and guarded rollback. The CLI emits human-readable or JSON reports.

The trust boundary is the local administrator's explicitly chosen PHP executable and configuration file. The tool neither fetches scripts nor executes shell commands from remote input. Read-only APT queries identify candidate package repositories but do not establish a signed package attestation or vendor backport status. It does **not** identify every active web SAPI, inspect application session handler changes, manage services or install PHP security updates.

Operations are bound to a selected PHP executable and its reported loaded INI. A different PHP-FPM or IIS worker may load another configuration. The configuration-change result proves at most CLI-level effectiveness until a real application health check and all production workers are independently verified. No unsigned auto-updater or third-party provider fallback exists.

An explicit `--verify --php PATH` checks that the selected executable can report an effective CLI configuration and a session upload-progress setting. It distinguishes a disabled setting (exit 0), an enabled setting (exit 2), and missing or invalid CLI inspection evidence (exit 3). An empty `ini_get` value for an explicitly reported setting means disabled, and the JSON preserves that empty value. This does not validate any serving worker or upstream PHP security patch.

Risk controls include read-only default execution, eight-second PHP inspection timeout, specific action flags, secure backup directory, filesystem link rejection for modification paths, original and modified file hashes, protected rollback against out-of-band edits, and fail-closed post-apply verification. A stale transaction lock after a crash must be reviewed manually. Cross-process out-of-band configuration writers and arbitrary vendor installation layouts remain outside this release's authority.
