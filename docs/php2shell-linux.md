# PHP2Shell on Linux

Run `php2shell-fix scan --json` to inventory discoverable CLI binaries. Linux package-managed PHP may reside in multiple branch-specific paths, and a web server's PHP-FPM pool may load another configuration.

For a native Debian/Ubuntu installation, `php2shell-fix --plan-update --php /usr/bin/php --json` performs a read-only APT package check. It requires the selected PHP executable to resolve to a standard `/usr/bin/php<major>.<minor>` binary owned by the matching `php<major>.<minor>-cli` package. It inventories packages on that PHP branch, reads APT candidates, conservatively recognizes only official Ubuntu/Debian repository hosts, checks candidates against the upstream security-release floor, and runs a package-manager simulation. It refuses to produce an eligible preview when APT would remove packages, include unplanned dependencies or change PHP branches.

**This plan is not an execution authorization or proof that a running PHP worker is secure.** Package candidates built with security backports require an independent vendor CVE record. Mirrors or third-party repositories need explicit administrator verification, even if legitimate. APT may run maintainer scripts, change services and restart workers; backup and recovery procedures are external to this preview. Only the operator can use the printed candidate command after checking vendor advisories, application compatibility, maintenance windows and real web-server health probes.

For CVE-2026-109618/109619, inspect **vendor** advisories and installed package changelogs before planning an update. Debian/Ubuntu security packages, RHEL-compatible vendor packages and third-party PHP repositories can contain backported fixes without changing the upstream PHP version string. Use the existing trusted `apt`/`dnf`/vendor update path after checking dependency compatibility, backups and service health. The tool currently produces guidance and read-only APT queries; it does not install packages.

For CVE-2026-115560, the PHP project's temporary recommendation is `session.upload_progress.enabled=0`. The CLI can safely modify only the explicitly selected loaded INI. PHP-FPM commonly uses `/etc/php/<version>/fpm/php.ini`, separate from the CLI INI; the CLI check does not prove FPM behavior. Confirm server configuration provenance and perform an owned service restart and health check. Do not use an application-level `ini_set` as the mitigation for early request processing.

References: [PHP advisory](https://www.php.net/archive/2026.php#2026-10-21-5), [Red Hat CVE guidance](https://access.redhat.com/security/cve/cve-2026-109619).
