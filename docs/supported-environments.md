# Supported Environments and Validation Evidence

Supported statuses are `SUPPORTED`, `PARTIALLY_SUPPORTED`, `DETECTION_ONLY`, `UNTESTED`, and `UNSUPPORTED`. They apply to specific paths rather than entire operating systems.

| Environment | Status (October 27, 2026) | Implemented / tested boundary |
| --- | --- | --- |
| Windows 11 x64, PHP CLI | PARTIALLY_SUPPORTED | On October 27, 2026, the exact Windows amd64 executable built from `ff5b47c` ran `scan --php PATH --json` and `--verify --php PATH --json` against locally installed PHP 8.4.27. Both commands exited 0; scan reported `ASSESSMENT_ONLY`, `windows-client`, and `CONFIG_NOT_FOUND` for IIS, while verify reported `CLI_MITIGATION_VERIFIED` with an observed empty `upload_progress` value. The Windows configuration was not modified; production PHP workers remain unverified. Separate Windows Server CLI results appear below |

No IIS/FastCGI or PHP-core upgrade validation |
| Windows Server 2019 Standard Evaluation x64, PHP CLI | PARTIALLY_SUPPORTED (CLI configuration mitigation) | VirtualBox guest build 17763 passed the same physical CLI lifecycle on October 27, 2026 with PHP 8.5.12 NTS x64. No IIS/FastCGI or PHP-core upgrade validation |

| Plesk / cPanel / hosting platforms | UNSUPPORTED for mutation | Use the hosting vendor's supported update procedure |

Every JSON assessment includes a `platform` object with `distribution`, `family`, `package_manager`, `update_planning`, `status` and limitations. Windows reports an additional `iis` configuration-discovery section whose mappings remain `CONFIGURED_ONLY`. On Windows, classification reads the operating system's registry `ProductType` (Windows Server, domain controller, client, or unknown). On Linux it reads `/etc/os-release`; unknown distributions remain identifiable as generic Linux without pretending to have a safe vendor upgrade recipe. `--plan-update` is currently available **only for specifically verified native Debian/Ubuntu APT installations**.

This list is intentionally conservative. Physical evidence applies only to the particular CLI configurations listed, not to every Linux distribution, Windows version or Windows Server edition. Passing a Windows or Linux build does not certify a hosted PHP runtime. The tool does not elevate privileges, start services, change repositories, deploy updates, or upgrade PHP automatically.

The Debian, CentOS, and Alpine checks above ran in disposable Docker containers on October 27, 2026; they do not constitute physical Oracle VirtualBox guest testing. The disposable containers were removed and the temporary binary directory was deleted. Previously existing virtual machines and images were preserved.

The native Windows 11 verification above was read-only and specifically covers the installed PHP CLI; it does not show that IIS is running or that upstream PHP-core vulnerabilities were remediated. The separate native Windows test binary was built inside a disposable Docker build container. The later Windows Server CLI validation used separate, temporary VirtualBox guests; see [Windows Server physical QA evidence](validation/windows-server-2026-10-27.md).
