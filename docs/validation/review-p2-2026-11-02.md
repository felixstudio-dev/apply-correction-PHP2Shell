# PR #1 P2 follow-up validation

## PR #2 follow-up: quoted tokens (2026-11-03)

[Review comment 4450380977](https://github.com/felixstudio-dev/apply-correction-PHP2Shell/pull/2#discussion_r4450380977) was reproduced on `a89abfa`: whitespace following a double-quoted PATH/HOST name, or an appended empty quoted token, incorrectly made the name appear scoped. Regression assertions and real PHP 8.5.12 post-validation failed before correction.

Literal section names are now assembled from quoted and unquoted tokens before classification. The decoder follows the [PHP scanner's token rules](https://github.com/php/php-src/blob/PHP-8.5/Zend/zend_ini_scanner.l): double-quote syntax consumes adjacent spaces/tabs, while unquoted token contents and single-quoted contents retain significant spaces. Tests distinguish `[PA "TH"]` from `["PA" TH]`, preserve internal quote/bracket characters, and cover real scoped suffixes alongside bare names. Variables and constants are not evaluated by this helper; existing effective CLI post-validation and safe restore remain required.

All 31 real-INI fixtures passed apply, effective CLI verification and exact rollback across the seven upstream PHP versions listed below (217 synthetic lifecycles). Native Windows tests/vet/build, Linux cross-vet/build and the isolated Linux mitigation suite passed. Independent read-only review found no concrete issue in the focused literal-token implementation.

Human approval on `a89abfa` does not cover this subsequent correction. No production change or merge is part of this validation.

## PR #2 follow-up: bare section names (2026-11-03)

[Review comment 4450304506](https://github.com/felixstudio-dev/apply-correction-PHP2Shell/pull/2#discussion_r4450304506) was reproduced on `71ec459` with six ordinary-section fixtures and real PHP 8.5.12. Bare PATH/HOST names, including quoted and lowercase names followed by comments, incorrectly caused insertion before a later global `On`; the CLI post-check failed and restored the original file.

The parser now excludes the section terminator/comments and requires a nonempty suffix after PATH/HOST before treating a section as scoped. Whitespace remains significant. Only a matching pair of external quotes is removed, preserving opposite quote characters inside names; independent review identified and corrected that edge case before publication. This follows PHP's [section callback and nonempty key-length guard](https://github.com/php/php-src/blob/PHP-8.5/main/php_ini.c). The change does not treat ordinary sections as resetting an already active scope.

All nineteen fixtures passed apply, effective CLI verification and exact rollback on the same seven upstream PHP versions listed below (133 synthetic lifecycles). Native Windows tests/vet/build, Linux cross-vet/build and the isolated Linux mitigation suite passed. Independent read-only review found no remaining concrete issue in the focused diff after correcting quote preservation.

The human approval of `71ec459` predates this correction and does not cover its new commit. Production and web-worker limitations remain unchanged.

## PR #2 follow-up: section-name whitespace (2026-11-03)

[Review comment 4446043434](https://github.com/felixstudio-dev/apply-correction-PHP2Shell/pull/2#discussion_r4446043434) identified an additional reproducible failure on `c7db28e`: leading spaces or tabs inside a section name were stripped before PATH/HOST classification. PHP preserves that whitespace for this classification, so an ordinary section could be mistaken for a scoped section and the inserted setting could be overridden by a later global value. Both the regression assertion and real PHP 8.2.35 post-check failed before the fix.

The parser now preserves that whitespace. Three additional fixtures cover leading space, tab and a quoted name with leading space. All eleven fixtures passed apply, effective CLI validation and exact rollback on each of PHP 7.4.33, 8.0.30, 8.1.34, 8.2.35, 8.3.36, 8.4.27 and 8.5.12 (77 synthetic lifecycles). Native Windows tests/vet/build, Linux cross-vet/build and the isolated Linux mitigation suite passed. A read-only independent agent review found no concrete issue in the focused diff. The human approval of `c7db28e` predates this correction; the updated commit needs renewed review. Production and web-worker limitations below still apply.

Legacy relative records used from an unrelated directory remain refused; use the original working directory or manually reconcile recovery evidence. Configuration rollback does not undo package changes.
