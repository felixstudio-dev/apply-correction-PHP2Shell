# PR #1 P2 follow-up validation

## PR #2 follow-up: section-name whitespace (2026-11-03)

[Review comment 4446043434](https://github.com/felixstudio-dev/apply-correction-PHP2Shell/pull/2#discussion_r4446043434) identified an additional reproducible failure on `c7db28e`: leading spaces or tabs inside a section name were stripped before PATH/HOST classification. PHP preserves that whitespace for this classification, so an ordinary section could be mistaken for a scoped section and the inserted setting could be overridden by a later global value. Both the regression assertion and real PHP 8.2.35 post-check failed before the fix.

The parser now preserves that whitespace. Three additional fixtures cover leading space, tab and a quoted name with leading space. All eleven fixtures passed apply, effective CLI validation and exact rollback on each of PHP 7.4.33, 8.0.30, 8.1.34, 8.2.35, 8.3.36, 8.4.27 and 8.5.12 (77 synthetic lifecycles). Native Windows tests/vet/build, Linux cross-vet/build and the isolated Linux mitigation suite passed. A read-only independent agent review found no concrete issue in the focused diff. The human approval of `c7db28e` predates this correction; the updated commit needs renewed review. Production and web-worker limitations below still apply.

The baseline regressions failed in all four affected packages; the scoped-INI failure was also reproduced using real upstream PHP 8.2.35. The corrected implementation passed native Windows unit tests, static analysis and build, Linux cross-vet/build, and isolated Linux tests. Real upstream PHP versions 7.4.33, 8.0.30, 8.1.34, 8.2.35, 8.3.36, 8.4.27 and 8.5.12 were tested in WSL mount/network namespaces with synthetic INIs. This does not attest vendor patches, cPanel behavior or live web workers. `PHP2SHELL_TEST_PHP` enables the real-CLI integration test; ordinary CI runs do not claim that optional matrix unless the variable is supplied.

The INI change updates the selected INI's global setting; validation covers only CLI, and other SAPIs may share that INI. Existing per-path/per-host overrides are intentionally preserved. Unknown dynamic syntax is still subject to the existing post-change CLI validation and safe-restore path. Legacy relative records used from an unrelated directory remain refused; use the original working directory or manually reconcile recovery evidence. Configuration rollback does not undo package changes.

Reference behavior was checked against PHP's [INI callback](https://github.com/php/php-src/blob/PHP-8.2/main/php_ini.c), [INI scanner](https://github.com/php/php-src/blob/PHP-8.2/Zend/zend_ini_scanner.l), and APT's [source documentation](https://manpages.debian.org/bookworm/apt/sources.list.5.en.html).
